DIZZY HUNTERS – TRAINER-XP

1) Supabase > SQL Editor: SUPABASE_TRAINER_XP.sql vollständig ausführen.
2) Supabase > Edge Functions > Deploy new function > Via Editor:
   Name exakt: trainer-xp
   Inhalt: supabase/functions/trainer-xp/index.ts
   Deploy klicken.
3) Edge Functions > trainer-xp > Details: Verify JWT = OFF.
   WICHTIG: Die Function prüft stattdessen die individuelle Trainer-PIN und das serverseitige Sitzungstoken.
   SUPABASE_SERVICE_ROLE_KEY und SUPABASE_URL sind normalerweise automatisch als Supabase Function Secrets verfügbar.
   Niemals Service-Role-Key in GitHub oder in die HTML/JS-Dateien eintragen!
4) Diese drei Dateien im GitHub-Repository dizzyhunters.github.io hochladen:
   missionen.html, trainer-xp.js, trainer-xp.css
   Die anderen bestehenden Dateien nicht überschreiben.
5) Website neu laden, im Dizzy Bereich > Missionen & XP ein Profil registrieren.
   Eine Mission abhaken und Rangliste kontrollieren.

HINWEISE:
- Bestehende Missionen und deren XP werden weiterverwendet. Bei späteren XP-Änderungen einer Mission ändert sich die Rangliste entsprechend.
- Mitgliedsgebundene Missionen müssen exakt den SSO-Namen enthalten; sonst sind sie nur dem jeweiligen Namen zugeordnet.
- Das gemeinsame Mitgliederpasswort bleibt bestehen; diese Funktion verwendet zusätzlich individuelle PINs.
- PINs sind serverseitig mit PBKDF2 + Salt gespeichert, aber keine vollständige Identitätsprüfung. Jeder mit dem gemeinsamen Passwort kann neue Namen anlegen. Für höhere Sicherheit sind persönliche Konten/Einladungen nötig.
- Bei PIN-Verlust kann die Leitung im Supabase Table Editor das Trainerprofil löschen; damit gehen auch dessen Mission-Häkchen verloren. Nicht unüberlegt löschen.
- Die öffentliche Rangliste zeigt SSO-Namen, XP und Rang. Kein privater Inhalt in SSO-Namen eintragen.
- Die Anzeige aktualisiert sich bei geöffneter Seite ungefähr alle 30 Sekunden und sofort nach einem Häkchen.
- GitHub Pages ist statisch; es sind keine Änderungen an der Leitungszentrale erforderlich.
